# HTML Communication

Create one self-contained HTML file whose form serves the requested decision or review.

- Treat the result as a technical artifact, decision document, or comparison surface rather than a marketing page.
- Build a clear hierarchy, useful navigation, readable tables, and responsive behavior.
- When alternatives are requested, label them and make direct comparison easy.
- Keep styles in the file. Avoid unnecessary external dependencies; if one is essential, document it.
- Preserve the project's brand direction. If none exists, choose a restrained visual system that fits the subject and audience.
- Do not invent metrics, claims, users, test results, or organizational context.
- Open the file in a browser and verify the rendered content, layout, links, overflow, and narrow-screen behavior.
- Return the absolute file path and the verification performed.
